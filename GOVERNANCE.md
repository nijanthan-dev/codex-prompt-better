# Governance

Prompt Better uses maintainer-led, issue-first governance during pre-alpha.
Maintainers set roadmap priority, review contributions, and protect privacy and
architecture boundaries. Decisions should be transparent in issues, PRs, and
ADRs. Security reports remain private until coordinated disclosure.

Changes require review proportional to risk. Architecture, persisted schemas,
execution policy, data retention, evidence adapters, and release processes need
explicit maintainer approval. Releases will use semantic versioning once the
project becomes installable.

Governance may evolve as contributors and maintainers grow; material changes
require an ADR and public PR.
